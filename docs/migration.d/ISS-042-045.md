## Early 0.7 fixes

- **`scs --version`** reports the installed package version (it reported 0.5.0 in 0.6.0).
- **cdmo SCD templates** no longer carry the header line `# Profile: Project only.`; the bundle
  that includes an SCD sets its scope.
- **Version manifests** record `content_digest` over the bundle's full resolved content, plus
  `content_inputs`, instead of a digest of the snapshot file that was never checked. Their
  `distribution` block reads `repository` and `branch` from git.
- **`scs bundle version --no-validate`** records `validation_passed: false` and
  `approval_status: approved`, instead of claiming the bundle was validated.
- **Runtime artifacts** carry `scs_runtime: '0.7'`. Runtimes that check `scs_runtime` should
  accept it; rules and facts are unchanged. The runtime schema still accepts `'0.6'`.
- **Editing an SCD after versioning is visible.** SCDs are not snapshotted: a bundle's versions
  and its working copy read the same SCD files. Once an SCD changes for the next version,
  earlier versions in the working tree no longer verify, and neither does a bundle that still
  pins them. Version the changed bundle, update the pins, and validate or compile older
  versions from their tag (`scs compile --version`). Comment and formatting edits don't change
  the digest.
