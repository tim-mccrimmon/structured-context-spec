## Versions, tags, and integrity

- **A version is a git tag.** `scs bundle version` commits the whole workspace (everything in
  it except `dist/`) and tags that commit `<workspace>/<bundle-name>-v<version>`, for example
  `domain/security-v1.0.0` or `app/prohibited-v1.0.0`. The tag is annotated. The commit's author
  is the approver; its committer and the tagger are `scs-tools <noreply@scs.invalid>`. Your git
  identity, signing settings, and hooks are not used. Edits in other workspaces, staged or not,
  stay out of the commit. Versioning needs git (`GIT_REQUIRED`).
- **`--force` and `--no-git` are gone**; both are usage errors. A released version is never
  overwritten (`VERSION_EXISTS`); choose a new version.
- **Snapshot and manifest names** follow the bundle name:
  `<bundle-name>-v<version>.yaml` and `<bundle-name>-v<version>-MANIFEST.yaml`, beside the bundle.
  The working bundle stays at `DRAFT`; the snapshot carries the released version.
- **The approver is a person**, `--approved-by "Name <email>"`. A plain email or `role:` value
  is refused (`VERSION_APPROVER_INVALID`). It is never taken from git configuration. In human
  mode, `bundle version` prompts for it; with `--json`, a missing approver is
  `VERSION_APPROVER_REQUIRED`.
- **Guards that `--no-validate` does not skip.** Every import must be pinned to a released
  version (`VERSION_IMPORT_NOT_PINNED`). A pinned import must match its version
  (`CONTENT_DIGEST_MISMATCH`) and have a 0.7 tag (`VERSION_TAG_MISSING`). A placeholder
  `created_by` is refused (`VERSION_PROVENANCE_PLACEHOLDER`), and so is a digest input that git
  ignores (`VERSION_INPUT_UNTRACKED`).
- **`bundle version` accepts `--json` and `--dry-run`.** A dry run lists the files it would
  create, the paths the commit would hold, the tag, and the bundle's empty SCDs.
- **Repository-mode validation checks the versions** (`scs-validate --strict` at the repository
  root):
  - every tag's content matches its manifest's `content_digest`;
  - the working copies of versions in use match their tagged copies (`MANIFEST_ALTERED`);
  - versions in use have not drifted.

  A shallow clone fails with `GIT_HISTORY_INCOMPLETE`; in CI, check out with `fetch-depth: 0`.
  `scs-validate --verify-version <tag>` checks one version.
- **Pre-0.7 versions are history.** Unqualified tags such as `v1.0.0`, and `VERSION-*`
  manifests without a `content_digest`, are not checked. A 0.7 root cannot pin them; version
  each imported bundle once under 0.7, re-pin, then version the root.
- **Resolution.** An unpinned import (`bundle:security`) resolves to the working bundle file. A
  pinned import (`bundle:security:1.0.0`) resolves to that version's snapshot.

## Compile

- **`scs compile <bundle> --version V`** compiles the released version from its tag, so edits
  made since then do not enter it. It needs the bundle's Domain repository.
- **`source_digest`** appears in an artifact only when the root was verified against its version
  manifest, which in practice means `--version`. An artifact compiled from a working `DRAFT` root
  has none. The examples' committed artifacts lost theirs for this reason.
- **Pinned versions are always verified.** A drifted pinned import stops the compile; no flag
  bypasses it. The diagnostic names the changed files and the bundles to version again,
  bottom-up.

## Diagnostics

- **Stub detection is removed**, along with `COMPLETENESS_STUB_SCD` and the `stub_detection`
  blocks in completeness rule files. An SCD with no prohibitions, directives, or facts is
  reported as `SCD_EMPTY` (info), so a fresh scaffold still passes `--strict`.
- **`PROVENANCE_PLACEHOLDER`** (warning) is new. It reports a `created_by` that names no one:
  `developer`, `Name <email>` with an empty name, or an address at `example.com`, `example.org`,
  `example.net`, `.example`, or `.invalid`. Teams, organizations, and real addresses pass.
  The 0.6 scaffold wrote `$USER@example.com`; correct those values before versioning.
- **Machine-mode paths** from `scs-validate --json` in repository mode are relative to the
  repository root.
