## Authors and approvers

- **No invented authors.** `scs new`, `scs add`, and `scs init` no longer fall back to `$USER`
  and `$USER@example.com`. In interactive mode they prompt, offering git's `user.name` and
  `user.email` as defaults. With `--no-interactive` or `--json`, `--author` and `--email` are
  required (`NO_INPUT`, exit 3); git's values appear only in the diagnostic's `suggestion`.
  `scs add` prompts in human mode and requires both in machine mode.
- **`bundle version` no longer prompts for the approver.** `--approved-by "Name <email>"` is
  required in every mode (`VERSION_APPROVER_REQUIRED`); git's identity is offered only as the
  `suggestion`.

## Scaffolding

- **A new Project inherits its Domain's ontology.** `scs new project` without `--ontology` uses
  the Domain workspace's `ontology` from `.scs/config` (sdlc if unset). `--ontology` still
  selects any ontology.
- **`scs new domain` and `scs new project` accept `--dry-run`.** The dry run lists every file,
  and for `new domain` the `git-init` and `git-commit`, and writes nothing.

## Maintaining a workspace through the engine

New commands, each with `--json`, `--dry-run`, and `--workspace`:

- `scs bundle pin NAME --version V [--bundle B]` re-pins B's one import of `bundle:NAME` to a
  released version. The default B is the workspace's root bundle.
- `scs bundle add-import REF [--bundle B]` adds an import that resolves in the workspace.
- `scs bundle add-scd SCD_ID --bundle B` lists an existing SCD in a bundle.
- `scs bundle remove-scd SCD_ID [--bundle B]` retires an SCD.
  - It removes the SCD from its bundle, and deletes the SCD file when no other bundle lists it.
    Released versions keep it at their tags.
  - A concept bundle left with no SCDs is removed, together with the imports of it and its
    ontology manifest entry.
- `scs add bundle NAME --new [--title T] [--description D]` creates a concept that has no
  template. It writes the concept bundle and a first, empty SCD, adds the ontology manifest
  entry, and adds `bundle:NAME` to the root bundle's imports.

These edit the files' text, so comments and layout survive.

## Versioning failures

- A failed `bundle version` now restores the working tree, the index, and refs, whatever step
  failed. The envelope's `changes` is then empty.
