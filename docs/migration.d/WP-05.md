## CLI

- **Machine mode.** `scs --version`, `scs validate`, `scs compile`, `scs add scd`,
  `scs add bundle` and the new `scs scd write` accept `--json`. Under `--json`, stdout carries
  exactly one result envelope (`schema/cli/envelope-schema.json`) with `changes`,
  `diagnostics` and `result`; human text goes nowhere. Paths in the envelope are relative to the
  repository root.
- **Exit codes.** 0 success, 1 errors, 2 warnings under `--strict`, 3 usage error (including
  unknown options and missing arguments, which click reported as 2 in 0.6), 4 file error,
  5 internal error. Scripts that checked for exit 2 on a usage error should check for 3.
- **Dry runs.** Commands that write files accept `--dry-run` and report the same `changes` they
  would make, without writing.
- **`scs compile` output.** The artifact is now written to
  `dist/<bundle-name>-<version>.<format>` in the workspace instead of stdout. Use `--stdout`
  for the 0.6 behaviour, or `--output` for another path inside the repository; a path outside
  it is refused (`OUTPUT_OUTSIDE_REPO`).
- **`scs scd write PATH --from-file FILE`** (`-` for stdin) validates an SCD and writes it only
  if it is valid. It is the supported way for agents and scripts to write SCD content.
- **Workspaces.** `scs add` takes `--workspace domain` or `--workspace <project>`. At the root
  of a Domain repository it is required (`WORKSPACE_REQUIRED`).
- **Reserved names.** `scs add bundle plan` (or `test-plan`, `qa`) is refused
  (`RESERVED_BUNDLE_NAME`).
- **Validator dependency.** scs-tools now depends on scs-validator and calls it in-process;
  the `validator` extra is no longer needed. No `scs` command opens a network connection.
