## Validator

- **Repository mode.** At the root of a Domain repository, `scs-validate` with no other input
  (or `scs-validate --repo <dir>`) validates every workspace: `domain/` and each
  `projects/<name>/`. It reports per workspace and exits with the worst result. A repository
  needs exactly one workspace whose `.scs/config` has `bundle_type: domain`.
- **Diagnostic codes.** Every finding in `--output json` now carries `code` and `severity`.
  Codes are listed in `schema/diagnostics/codes.yaml`; the report format is
  `schema/validator/report-schema.json`. A new `info` severity never changes the exit code,
  including under `--strict`.
- **Reserved names.** Bundles named `plan`, `test-plan`, or `qa` are errors
  (`RESERVED_BUNDLE_NAME`); rename them. Directories with those names at a workspace root are
  ignored.
- **Duplicate ids.** Two SCDs with one id, or two bundle files with one id and version, in a
  workspace are errors (`DUPLICATE_ID`). Snapshots of different versions are not duplicates.
- **Workspace name.** In repository mode, the `name` in `.scs/config` (or `project_name`, for
  0.6 workspaces) must equal the workspace name: `domain`, or the directory name under
  `projects/` (`CONFIG_NAME_MISMATCH`).
- **Ontology manifest.** `ontology/domain-manifest.yaml` is the 0.7 location. The 0.6 location,
  `domain/domain-manifest.yaml`, still works and is reported as info
  (`ONTOLOGY_LEGACY_LOCATION`).
- **Version manifests.** In repository mode, `<bundle-name>-v<version>-MANIFEST.yaml` files are
  checked against `schema/manifest/version-manifest-schema.json`. The approver must be a person,
  written `Name <email>`. Manifests named `VERSION-<version>-MANIFEST.yaml` predate 0.7 and are
  not checked.
- **Rules.** The default rule set is now `rules/v0.7.0`.
