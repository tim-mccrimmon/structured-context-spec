## Intake record and provenance

- **`intake.yaml`** at a workspace's root (`domain/intake.yaml`, `projects/<name>/intake.yaml`)
  records the intake: routing answers, profile answers, approvers, source documents, intake
  answers, and review findings. It is optional, not an SCD, and never compiled. It is validated
  against the new `schema/intake/intake-schema.json` in bundle and repository mode
  (`INTAKE_SCHEMA_INVALID`). It is part of every version commit.
- **Two commands write it**, each with `--json`, `--dry-run`, and `--workspace`; do not edit it
  by hand:
  - `scs intake set FIELD VALUE` sets one field. VALUE is YAML, and `-` reads stdin. An object
    given for `answers` or `source_documents` replaces the entry with the same `id` or is added;
    for `approvers` the key is `person`. Anything else replaces the field. An answer without
    `answered_at` gets the current time (UTC). `review_findings`, `intake_version`, and
    `scs_version` are refused (`INTAKE_FIELD_RESERVED`).
  - `scs intake record-finding --kind K --target T --finding F --decision D --decided-by P`
    records a review finding and the decision. `--id` defaults to the next `rf-N`, and
    `--decided-at` to now. `kept` needs `--rationale`. `--decided-by` is never taken from git
    (`NO_INPUT`, with git's identity as the `suggestion`).

  Both refuse a change that would make the record invalid, and write nothing.
- **People** in the record are `Name <email>`, or `role:<name>` for a repository that will be
  shared publicly. `owner` must be a person. Approvers are `{person, role}`, where `role` is a
  job title.
- **`derived_from`** is a new optional list on prohibitions, directives, and facts. Each entry
  has exactly one of `intake` (an answer id) or `source` (a source document id), plus an
  optional `locator`. An id that is not in the workspace's own `intake.yaml` is
  `DERIVED_FROM_UNRESOLVED` (warning; exit 2 under `--strict`). `scs compile` never emits it.
- **Bundle and repository validation now check every SCD in the tree against its tier schema.**
  Before this, only single-file validation did, so a schema error in an SCD could pass
  `--bundle`, `--repo`, and `scs bundle version`.
