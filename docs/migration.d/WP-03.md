## Domain repositories

- **`scs new domain NAME`** creates a Domain repository, `NAME-context/`, instead of a bare
  workspace `NAME/`. The Domain workspace is `NAME-context/domain/`; the repository also gets
  `projects/`, `AGENTS.md` with a `CLAUDE.md` pointer, `.github/workflows/scs-validate.yml`
  (runs `scs-validate --strict` with full history and tags), `.gitignore` (ignores `sources/`),
  and `.gitattributes` (`* text eol=lf`). It runs `git init` and makes one commit, authored and
  committed by `scs-tools <noreply@scs.invalid>`, whatever your git identity or settings.
  `scs new domain` now needs git (`GIT_REQUIRED`).
- **Templates follow the ontology only.** `scs new domain` and `scs new project` take
  `--ontology` (`sdlc`, the default, `cdmo`, `mca`, or `personal`) and scaffold that ontology's
  full concept and SCD set for the workspace kind; remove what you don't use. `--type` is gone
  from `scs new` (it remains on `scs init`), and there is no `--profile` or `--ontology none`;
  both are usage errors.
- **`--ontology personal`** is new: one person's context. Its only fixed concept is boundaries
  (the `prohibited` concept bundle), in the Domain and in each Project; other concepts are added
  as you define them.
- **Provenance.** `created_by` in scaffolded SCDs and bundles is `Name <email>`, built from
  `--author` and `--email`.
- **`scs new project NAME`** must run inside a Domain repository (or name one with `--dir`) and
  creates `projects/NAME/`. Outside one it fails with `DOMAIN_WORKSPACE_MISSING`. It does not
  commit. To keep using a standalone 0.6 workspace, use `scs init`.
- **Names.** `plan`, `test-plan`, and `qa` are refused (`RESERVED_BUNDLE_NAME`). A Project
  cannot be named `domain`, and no workspace can take a concept bundle's name, such as
  `security` (`WORKSPACE_NAME_INVALID`). An existing target is never overwritten
  (`WORKSPACE_EXISTS`).
- **Workspace layout.** The ontology manifest is written to `ontology/domain-manifest.yaml`
  (the 0.6 location, `domain/domain-manifest.yaml`, is still read). Workspaces no longer get a
  `VERSION` file or their own `.gitignore`; the repository root has the `.gitignore`.
- **`.scs/config`** keys are `bundle_type`, `name` (the workspace name: `domain` or the
  Project's directory name), `ontology`, `scs_version` (the spec version, `0.7.0`), and
  `tools_version`; `project_type` is no longer written. The 0.6 keys `project_name` and
  `ontology_model` are still read.
- **Machine mode.** `scs new domain` and `scs new project` accept `--json`; the envelope lists
  every file created and, for `new domain`, the `git-init` and `git-commit`. `--dry-run` and
  the author rule for machine mode follow in WP-06.
