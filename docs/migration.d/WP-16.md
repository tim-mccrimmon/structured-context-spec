## Layered context

- **New command, `scs stack ARTIFACT...`.** Clients often load several compiled artifacts at
  once, for example a personal Domain, an organization's Domain, and a Project. `scs stack`
  previews that combination: give the artifacts outermost first, and it lists each layer and
  every rule and fact in stack order with the layer it came from. It reads only, and never
  merges, reorders, or drops a rule (`spec/0.7/runtime-artifact.md` §5).
- **Checks.** `STACK_BUNDLE_REPEATED` (error), `STACK_PROHIBITION_DIRECTED` (warning; exit 2
  under `--strict`), `STACK_RULE_DUPLICATE` and `STACK_LAYER_DRAFT` (info). An input that is not
  a runtime artifact is `STACK_ARTIFACT_INVALID`.
- **Nothing to migrate.** Existing artifacts work as inputs, including 0.6 artifacts
  (`scs_runtime: "0.6"`), which the runtime schema still accepts.
